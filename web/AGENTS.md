# web/

## Purpose

TanStack Start **web client** for OpenSen: marketing/landing and the authenticated web application in one Vite + Nitro project.

## Ownership

- Routes under `src/routes/` (file-based; `src/routeTree.gen.ts` is generated by the Vite plugin and committed)
- Components and libraries under `src/components/` and `src/lib/`
- Static assets under `public/` (served from `/`, including `favicon.ico`, `icon.png`, `apple-icon.png`)
- Vite / Nitro / Vercel deploy config for this package (`vite.config.ts`, `vercel.json`, `.npmrc`)
- Product behavior lives in [`docs/`](../docs/); this tree owns web UI implementation
- API calls go to [`backend/`](../backend/) — do not reimplement server business logic here

## Local Contracts

- Framework: [TanStack Start](https://tanstack.com/start) on Vite 8 + Nitro (TypeScript, Tailwind CSS v4 via `@tailwindcss/vite`, ESLint flat config). Nitro picks the Vercel preset on Vercel builds and the Node server elsewhere.
- Package name: `opensen-web` (see `package.json`). ESM (`"type": "module"`).
- Production host: `https://opensen.taquangkhoi.com/`
- Run from this directory: `npm install`, `npm run dev` (port 3001), `npm run build`, `npm run start`, `npm run typecheck`, `npm run lint`, `npm test`. `.npmrc` sets `legacy-peer-deps` because `@neondatabase/auth` still declares a `next` peer.
- Import alias: `@/*` → `src/*`. Paths below are relative to `src/` unless they start with `web/`.
- Entry points: `router.tsx` (router, Sentry router tracing, plain-string search serializer from `lib/routing/search.ts` so `?i=1`, `?add=1`, `?redirectTo=…` look like the old URLs), `start.ts` (global request/function middleware), `client.tsx` (imports `instrument.client.ts` first), `server.ts` (imports `web/instrument.server.mjs` first, wraps fetch with Sentry).
- Route layout: `routes/__root.tsx` (document shell, default title/description, icons, stylesheet, analytics); `routes/index.tsx` (landing, public CDN cache); pathless `routes/_app.tsx` (signed-in layout + `QueryProvider`); `routes/_app/_shell.tsx` (study shell); `auth.sign-in`, `auth.sign-up`, `account.settings`, `api.auth.$` (Neon Auth proxy), `monitoring` (Sentry tunnel). Unknown paths and `notFound()` render `components/not-found-page.tsx` with HTTP 404; route errors render `components/route-error.tsx`.
- Metadata: each route sets `head` with `pageTitle(...)` from `lib/page-title.ts` (`<title> · OpenSen`). Dynamic titles come from the loader (`learn/$topic`, `learn/$topic/$step`), which throws `notFound()` for unknown ids.
- Env: browser values use `VITE_*` (`import.meta.env`, inlined at build, typed in `vite-env.d.ts`). Server values (`NEON_AUTH_*`, `SENTRY_DSN`) are read from `process.env` inside server code at request time, never at module scope.
- API base URL: `resolveApiBaseUrl()` in `lib/api/client.ts`. `VITE_OPENSEN_API_URL` overrides; otherwise production builds call the public API `https://api.opensen.taquangkhoi.com` (hardcoded, not secret, no Vercel env needed) and non-production builds call `http://localhost:3000`. The API must list the web origin in `CORS_ORIGINS` (backend default already includes `https://opensen.taquangkhoi.com`).
- Page analytics: `onedollarstats` initialized in the root route via `components/onedollarstats-analytics.tsx`; env vars documented in `.env.example` (`VITE_ONEDOLLARSTATS_*`)
- Error monitoring and tracing: `@sentry/tanstackstart-react`. Browser init in `instrument.client.ts` (`VITE_SENTRY_DSN`, `tunnel: "/monitoring"`); server init in `web/instrument.server.mjs` (`SENTRY_DSN`), imported at the top of `server.ts` because Vercel cannot pass `node --import`. `start.ts` registers `sentryGlobalRequestMiddleware` / `sentryGlobalFunctionMiddleware` first. `sentryTanstackStart` in `vite.config.ts` (last plugin) uploads source maps with `SENTRY_AUTH_TOKEN`, `SENTRY_ORG`, `SENTRY_PROJECT`. The tunnel is our own route `routes/monitoring.ts` (`createSentryTunnelRoute`, POST only, GET 405), not the plugin's managed `tunnelRoute`, which pulled the whole browser SDK (Replay, Feedback) into the main chunk. Production browser ingest: `https://opensen.taquangkhoi.com/monitoring`. Project is `do-quyen` / `opensen-web`. Browser traces propagate to `localhost`, `https://api.opensen.taquangkhoi.com`, and same-origin requests. The auth middleware does not cover `/monitoring`.
- Error reporting rule: every failure message a learner can see is sent to Sentry exactly once, through `captureOperationalError` in `lib/observability/operational-error.ts` (`@sentry/core`, the client registered by `Sentry.init`). Level `error` means our side broke (network, invalid JSON, HTTP >= 500, auth SDK 5xx, unexpected throw). Level `warning` means the request or setup caused it (HTTP 4xx, auth SDK 4xx, empty form field, dialogue persistence off, speech or storage refusal). Owners:
  - API: `createDefaultApiClient` reports every failed request through `reportApiError` (`lib/api/client.ts`), with the thrown `fetch` message and bearer shape/length (never the token). The Anki download (`lib/query/hooks/export.ts`) calls `reportApiError` too. Screens on these paths only render the banner and must not report again.
  - Non-API throws inside query or mutation functions: `QueryCache` / `MutationCache` `onError` in `lib/query/query-client.ts` (`reportUnexpectedQueryError`, skips `ApiError`).
  - Auth forms (sign-in, sign-up, account name): `reportAuthFormError` (`lib/observability/auth-form-error.ts`).
  - Speech: all browser TTS goes through `speak` in `lib/speech/speak.ts` (studio uses it via `components/studio/speak.ts`); `interrupted`/`canceled` from our own cancel are not reported.
  - Storage: `lib/settings/learner-settings.ts` (read once per load, every failed write) and `lib/practice/focus-queue.ts` (corrupt handoff).
  - Persistence-off messages in `components/onboarding/` and `components/dialogues/dialogue-builder.tsx`; the too-few-variants message in `components/drills/substitution-drill-session.tsx`.
  - Render crashes: `components/route-error.tsx` (router `defaultErrorComponent`). Uncaught errors and rejections: the SDK's global handlers; server request and server function errors: the Sentry global middlewares in `start.ts`.
  - Not reported, because they are correct outcomes rather than failures: a wrong drill answer ("Not quite — try again."), "Nothing to export", and empty lists.
- Server state: [TanStack Query](https://tanstack.com/query/latest) v5 (`@tanstack/react-query`, devtools in development only). `QueryProvider` (`lib/query/query-provider.tsx`) is mounted by `routes/_app.tsx` and owns one `QueryClient` plus one `createDefaultApiClient` instance (`useApiClient()`). `routes/index.tsx` mounts a separate provider so the landing CTA can read account onboarding status; that cache is not the signed-in app cache. Leaving `_app` (sign-out redirects to `/auth/*`) unmounts the app provider, which drops that cache so it never crosses learners; do not hoist one provider into the root route. Defaults in `lib/query/query-client.ts`: `staleTime` 30s, queries retry only `isRetryable` failures up to 2 times (each attempt is a separate Sentry report from the client), mutations never retry. Keys come only from `queryKeys` (`lib/query/query-keys.ts`), prefixed by domain (`situations`, `chunks`, `dialogues`, `practice`, `savedSentences`, `onboarding`); `practiceSessionDeck` sits outside `practice` on purpose so grading does not reshuffle a running session.
- Auth: Managed Better Auth through `@neondatabase/auth`. The bundled server adapter targets Next.js, so `lib/auth/auth.server.ts` builds a TanStack Start adapter on `@neondatabase/auth/server` (`createAuthServer` with a `RequestContext` over `getRequest`/`setCookie`, `handleAuthProxyRequest`, `processAuthMiddleware`). It is server-only (`.server.ts`), reads `NEON_AUTH_BASE_URL` and `NEON_AUTH_COOKIE_SECRET` at first use, and keeps the `__Secure-neon-auth.*` cookie names, so sessions survive the cutover. Browser client: `lib/auth/client.ts`. Server functions in `lib/auth/auth.functions.ts`: `getSessionUser`, `signInWithEmail`, `signUpWithEmail`, `updateDisplayName`, `signOut` (each authorizes itself; success throws a router `redirect`). Route protection: `authRequestMiddleware` (`lib/auth/auth-middleware.ts`, registered in `start.ts`) runs on document requests under `protectedPathPrefixes` (`lib/auth/protected-routes.ts`: study shell, onboarding, settings, account, …), answers 307 to `/auth/sign-in?redirectTo=<path+search>` when signed out, appends refreshed session cookies, and sets `Cache-Control: private, no-store`. `routes/_app.tsx` `beforeLoad` repeats the check on client navigation into the app. `/` and `/auth/*` stay public. API proxy: `routes/api.auth.$.ts`.

## Work Guidance

- Components render on the server for the first request and hydrate in the browser; there are no Server Components or `"use client"` directives. Browser-only APIs (`window`, `localStorage`, speech) stay inside effects or event handlers.
- Privileged reads and writes go through `createServerFn` (or a server route) and authorize inside the handler; a route guard is UX, not authorization. Never import `*.server.ts` from components.
- Links: `AppLink` (`components/app-link.tsx`) for `AppRoutes` string hrefs (path + query); it uses the router `Link` for in-app paths and a plain `<a>` for hash and external links. Imperative navigation: `useAppNavigate()` (`lib/use-app-navigate.ts`). Current path: `useLocation`. Search params: `validateSearch` + `Route.useSearch()` with `optionalString`.
- Keep marketing (`routes/index.tsx`) and the signed-in app (`routes/_app/…`) in separate route subtrees.
- Images are plain `<img>` with explicit `width`/`height`; there is no image optimizer, so ship pre-sized assets (e.g. `public/onboarding/onboarding-mascot-wave-192.png`). Fonts are self-hosted Fontsource variable fonts imported in `styles.css` (Geist, Geist Mono, Nunito, Caveat; `font-display: swap`), exposed through the `--font-*` variables.
- All backend HTTP calls go through `lib/api/` (`createDefaultApiClient` or route helpers under `lib/api/routes/`). Do not scatter raw `fetch` with hand-rolled auth headers.
- Components read and write server state only through the hooks in `lib/query/hooks/` (`situations`, `chunks`, `dialogues`, `practice`, `export`, `saved-sentences`, `onboarding`). Do not fetch in `useEffect` or hold API responses in `useState`. Query functions wrap route helpers with `unwrapApiResult`; render errors with `queryErrorMessage`. Show a load error only when no data is cached, so a failed background refetch keeps the screen usable. A mutation's `onSuccess` invalidates every domain whose data it changes (review → `practice`; chunk create/edit → chunk lists, edit also `practice`; persisted dialogue generation → chunks, practice, dialogues, situations; saving or unsaving a sentence → `savedSentences`). Onboarding completion writes `queryKeys.onboarding.status` directly.
- Learner identity is the Neon Auth session. `createDefaultApiClient` sends `Authorization: Bearer <jwt>` from `getSessionToken` (`lib/api/session-token.ts`, which reads `authClient.getSession()` → `session.token`). That field only holds the JWT when the `get-session` response carries `set-auth-jwt`, so `proxyAuthRequest` (`lib/auth/auth.server.ts`) sends browser `get-session` calls past the `session_data` cookie cache (`disableCookieCache=true`). Without that, the cached answer leaves the opaque session token in place and every API call returns 401 "Invalid or expired token". Signed-out calls go out without the header, and user-scoped API routes answer 401. Use `getSessionToken` only from client components or hooks. The one raw `fetch` (Anki export download, `lib/query/hooks/export.ts`) uses it too and saves `opensen-anki-${scope}.apkg` (`application/apkg`). `AnkiExportPanel` only chooses the scope and calls `useAnkiExport`.
- The signed-in shell is the study UI in `components/studio/` and `components/app-shell.tsx`. The desktop sidebar account control shows the signed-in learner’s name, not the fixed word Profile. The live source is the Neon Auth session (`authClient.useSession()` → `user.name`). Until that session is in memory, the shell route loader’s `getSessionUser().name` fills the same label. `sidebarAccountLabel` (`lib/auth/sidebar-account-label.ts`) trims the name and, when it is missing or blank, shows `Account`. The compact bottom-nav control uses that label as its accessible name. Both still link to `/profile`. Flutter’s bottom nav has no Profile destination. Primary routes: `/home`, `/learn`, `/learn/$topic`, `/learn/$topic/$step`, `/practice`, `/practice/speak`, `/practice/done`, `/explore`, `/library`, `/profile`, `/saved`, `/saved/$id`. `/saved` lists sentences on the signed-in account (`useSavedSentences`, `useSaveSentence`, `useUnsaveSentences`). **Add a sentence** opens the composer (one sentence, then save). The filled star on a row removes that sentence. Library’s Saved tab and the star on a lesson sentence use the same list (`useSavedSentenceListActions` in `lib/query/hooks/saved-sentences.ts`, matching in `lib/saved-sentences/library-list.ts`). Starring a lesson inserts that sentence’s text; unsaving in either place deletes the row. Topic tabs stay `listLibraryItems()`. `StudioProvider` does not keep saved ids. Library’s **Add a sentence** button lands on `/saved?add=1` with the composer open. `/saved/$id` opens that sentence and enters the existing lesson practice deck (`startLessonPractice` → `/practice`). Lesson copy and the practice deck live in `lib/studio/content.ts`. Older recall, plan, situation, and chunk screens stay reachable from Explore (`/today`, `/plan`, `/situations`, `/patterns`), which also links to `/saved`.
- Sign-in and sign-up are the email forms at `/auth/sign-in` and `/auth/sign-up` (`components/auth/*-form.tsx`, calling the auth server functions through `useServerFn` + `useActionState`). Account name edits live at `/account/settings`. After sign-in or sign-up, return to the requested path when `redirectTo` is present, otherwise `/home`.
- `/onboarding` reads `GET /api/onboarding` before showing the wizard (`OnboardingGate`). When the account’s `users.onboarding_completed_at` is set, the route replaces itself with `/home`. Settings → Redo onboarding sends `PUT /api/onboarding` with `complete: false`, then opens the wizard. A browser that still has the old `opensen:onboarding-complete` localStorage key, and an account that is not finished, copies that completion onto the account once.
- Study illustrations live in `public/studio/` and are mapped by `components/studio/scenes.tsx`. Sen is the cream round character with the green leaf beret, glossy black eyes, and rosy cheeks. New scenes stay in that pastel storybook style and contain no UI chrome or readable text. `docs/DESIGN.md` still governs the calmer recall and plan surfaces.
- The marketing page is `components/landing-page.tsx`, with storybook art in `public/landing/`. Readable product copy on that page stays in HTML. Landing headlines live in `lib/site.ts` and match the Landing copy section of `docs/product-strategy.md`.
- The brand mark is `public/brand/logo.png` (transparent square crop of the lotus). Render it through `components/brand-mark.tsx` (`BrandMark`, and `LogoMark` in the study shell). Favicon and Apple touch icon are `public/favicon.ico`, `public/icon.png` (192px), and `public/apple-icon.png` (180px), linked from `routes/__root.tsx`.
- UI icons: [`@phosphor-icons/react`](https://github.com/phosphor-icons/react). Import the named component (`HorseIcon`). Vite tree-shakes the named imports, so only the icons in use ship. Default `weight="regular"`; `weight="fill"` for the selected or active state of the same icon. Size and color go through the icon props (`size`, `color`, or `currentColor`). Do not add Material, Lucide, Heroicons, or hand-rolled `<svg>` icons for UI chrome.
